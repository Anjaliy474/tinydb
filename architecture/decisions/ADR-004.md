# ADR-004: Dual-Layer State Using GitHub Actions Artifacts and Branch/PR Checkpoints

- **Decision ID:** D4 (State)
- **Date:** 2026-11-23

## Status

Accepted

## Context

The workflow requires two types of state:
1. **Within-Run State:** Passing stage artifacts (`spec.md`, `design.md`, `diff.patch`, `test_report.md`, `pr.md`, `review.md`) and `run_state.json` (token counts, retry counts, gate results) between isolated Actions jobs in a single run, while keeping the full audit trail visible on GitHub.
2. **Across-Run / Restart State:** If a run fails due to a transient error or a maintainer re-triggers `/autose`, the workflow must know whether branch `autose/issue-<N>` and an open PR already exist and how many review rounds have already been consumed—without polluting the target repository's PR diff with workflow metadata files.

### Options Considered

- **Option A — Commit Artifacts onto the Feature Branch:** Store `spec.md`, `design.md`, etc. inside `.autose/` on `autose/issue-<N>`. Rejected because it pollutes the PR diff on any target repository, leaks Stage 1–5 planning artifacts to the Stage 6 reviewer (violating ADR-003), and forces manual cleanup before merge.
- **Option B — GitHub Actions Cache (`actions/cache`) Only:** Store state in Actions cache. Rejected because cache entries can be evicted unpredictably and are not downloadable as permanent run artifacts in the GitHub UI.
- **Option C — Issue/PR Comments Only:** Dump full artifacts as comments. Rejected because large diffs and test logs make the issue thread unreadable and lack structured file separation.
- **Option D — Dual-Layer State: Actions Workflow Artifacts + Feature Branch & Hidden Status-Comment Checkpoint (Chosen):** Use [GitHub Actions workflow artifacts](https://docs.github.com/en/actions/tutorials/store-and-share-data) for per-run files and Git branch + a single bot status comment for cross-run idempotency.

## Decision

We separate intra-run and inter-run state into two layers:

1. **Intra-Run State (GitHub Actions Workflow Artifacts):**
   - Each job uploads its stage artifacts via `actions/upload-artifact` (30-day retention) using round-prefixed names (`r1-spec`, `r1-design`, `r1-diff`, `r1-test-report`, `r1-pr`, `r1-review`, and `r2-*` when Round 2 executes) plus `run_state.json`.
   - Downstream jobs download **only** the artifacts permitted by ADR-003 via `actions/download-artifact`.
   - Artifact upload steps use `if: always()` so failed or halted runs still preserve failure diagnostics.

2. **Inter-Run & Restart State (Deterministic Branch + Single Bot Status Comment):**
   - **Code State:** Always lives on a single deterministic branch `autose/issue-<N>` in the repository fork. Stage 5 checks `gh pr list --head autose/issue-<N>` before opening a PR; if one exists, it pushes new commits and updates the existing PR rather than opening a duplicate.
   - **Run Checkpoint:** A single bot-maintained status comment on the issue/PR stores a human-readable stage table plus a compact hidden JSON marker:
     `<!-- autose-state: {"issue": N, "pr": P, "review_rounds_used": 1, "last_stage": "review-r1", "last_run_id": "..."} -->`
   - **Restart Behavior:** When a maintainer re-runs a failed workflow or posts `/autose` again:
     - The intake step reads the hidden JSON marker and inspects `git ls-remote` / `gh pr list`.
     - If `review_rounds_used >= 2`, the workflow stops immediately and notifies the maintainer that the 2-round review cap is exhausted (requiring human takeover or an explicit `/autose reset`).
     - If a prior run stopped before Stage 5, the new run starts cleanly without creating duplicate branches or PRs.

## Consequences

### Positive

- **Zero PR Pollution Across Any Repository:** The target repository's feature branch contains only real code and test changes—never workflow scratch files.
- **Reviewer Isolation Preserved:** Stage 6 checks out the PR branch without ever seeing upstream Actions artifacts.
- **Idempotent Restarts:** Re-triggering `/autose` never duplicates PRs or resets the 2-round review cap.

### Negative

- **Artifact Expiration:** GitHub Actions artifacts expire after 30 days (configurable up to 90 days on public repos); long-term archival for reports relies on exporting run summaries/links.
- **Comment State Fallback Needed:** If someone manually deletes the bot status comment, the intake step falls back safely to checking `git ls-remote` for `autose/issue-<N>` and `gh pr list`.
