# ADR-010: Maintainer-Gated Dual Triggers with Per-Issue Concurrency Queuing

- **Decision ID:** D10 (Triggers)
- **Date:** 2026-11-23

## Status

Accepted

## Context

Maintainers must be able to trigger the workflow either by adding a label (`autose`) to an issue or by posting a command comment (`/autose`) on an issue or open pull request. On any public repository, external users can open issues or post comments; without strict authorization and concurrency controls, unauthorized triggers could drain API credits and simultaneous triggers on the same issue could cause conflicting branch pushes or duplicate PRs.

### Options Considered

- **Option A — Auto-Trigger on `issues: [opened]`:** Start the workflow automatically on every new issue. Rejected because it removes maintainer opt-in, wastes API credits on spam/out-of-scope issues, and expands prompt-injection exposure.
- **Option B — Repository-Wide Single-Run Concurrency Lock:** Allow only one workflow run across the entire repository at a time. Rejected because it unnecessarily blocks independent issues from running in parallel.
- **Option C — Maintainer-Gated Dual Triggers + Per-Issue Concurrency Group (Chosen):** Trigger only on maintainer-authorized `autose` label or `/autose` comment, and serialize concurrent runs per issue number.

## Decision

### 1. Trigger Events & Filtering
`.github/workflows/autose.yml` listens to two events:
```yaml
on:
  issues:
    types: [labeled]
  issue_comment:
    types: [created]
```
Job-level `if:` filters reject non-matching events before any agent runs:
- `issues`: `github.event.label.name == 'autose'`
- `issue_comment`: `startsWith(github.event.comment.body, '/autose')`

### 2. Authorization & Safety Checks
- **Maintainer-Only Gate:** Only actors with `OWNER`, `MEMBER`, or `COLLABORATOR` association (verified via `gh api repos/$REPO/collaborators/$ACTOR/permission` requiring `admin`, `maintain`, or `write`) may trigger runs. External commenters are ignored cleanly.
- **No Bot Self-Triggering:** Events where `github.actor == 'github-actions[bot]'` or `endsWith(github.actor, '[bot]')` are always skipped.
- **Fork-Only & Human-Merge Policy:** The workflow verifies it is running on the team's owned repository (never upstream). Because GitHub Actions withholds repository secrets from external fork PRs, external forks cannot access API keys. Branch protection on the default branch ensures only a human maintainer can merge.

### 3. Concurrency Control
A workflow-level [`concurrency:`](https://docs.github.com/actions/using-workflows/workflow-syntax-for-github-actions) group serializes runs per issue/PR number:
```yaml
concurrency:
  group: autose-issue-${{ github.event.issue.number }}
  cancel-in-progress: false
```
- **Two Simultaneous Runs on the Same Issue:** The second run queues safely (`cancel-in-progress: false` avoids interrupting a mid-flight `git push` or artifact upload). When the queued run starts, it reads the updated branch and bot status comment (ADR-004); if the PR is already reviewed or the 2-round cap is reached, it exits cleanly as a no-op.
- **Two Simultaneous Runs on Different Issues:** Distinct concurrency groups (`autose-issue-1`, `autose-issue-2`) run in parallel without blocking each other.

## Consequences

### Positive

- **Zero Unauthorized API Spend:** Public users can file issues, but only authorized maintainers can invoke LLM agents.
- **Eliminates Race Conditions:** Per-issue queuing prevents conflicting pushes to `autose/issue-<N>` and duplicate PRs while preserving parallelism across distinct issues.
- **Human Remains Final Decision Maker:** Branch protection plus no merge tool guarantees a person always decides whether to merge or close.

### Negative

- **GitHub Queues At Most One Pending Run Per Group:** If three triggers fire rapidly on the same issue, GitHub supersedes the middle pending run with the latest—which is acceptable and prevents redundant duplicate runs.
- **Manual Maintainer Opt-In Required:** External contributors cannot self-trigger the bot without a maintainer applying the `autose` label or posting `/autose`.
