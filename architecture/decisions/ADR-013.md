# ADR-013: Move the agents from the Gemini free tier to DeepSeek

- **Decision ID:** D6 (Models), revisited a second time
- **Date:** 2026-11-23
- **Supersedes:** ADR-011

## Status

Accepted

## Context

ADR-011 put the agents on Gemini's free tier because there was no paid API access. Five runs on
issue #3 showed it can't carry the project:

| Run | What happened |
| :--- | :--- |
| [45169044955](https://github.com/Anjaliy474/tinydb/actions/runs/45169044955) | Planner wrote a good spec, then sat waiting on rate limits until the 20-minute job limit |
| [45172879048](https://github.com/Anjaliy474/tinydb/actions/runs/45172879048) | Fast, but stopped on a vague criterion (led to ADR-012) |
| [45173736214](https://github.com/Anjaliy474/tinydb/actions/runs/45173736214) | Planner passed; builder's model answered 503 then 504 and the job crashed |
| [45175052013](https://github.com/Anjaliy474/tinydb/actions/runs/45175052013) | Planner passed; builder's model had no daily quota left |
| [45177060069](https://github.com/Anjaliy474/tinydb/actions/runs/45177060069) | Got through: [PR #16](https://github.com/Anjaliy474/tinydb/pull/16) has the right fix, passes all 3 hidden tests and CI. But the builder alone took about 45 minutes, mostly waiting on Gemini |

Each run fixed a real weakness in the harness (better retries, fail-fast on quota, model
fallback), and the fifth run showed the design works end to end. But four of the five runs
failed because the free models were overloaded or out of quota, never for lack of ability, and
the one that got through needed almost an hour for a one-line fix. The daily caps are also too
small for the remaining 4 issues, the seeded PRs and the two experiments the assignment needs.

A DeepSeek API key is available. DeepSeek bills per token at low prices (peak rates: Flash
$0.30 in / $1.20 out per 1M tokens, V4 Pro $1.32 / $3.96), uses the OpenAI chat format with tool
calls, and offers two different models.

### Options considered

- **A: stay on the Gemini free tier and wait for quotas to reset.** Costs nothing, but runs keep
  failing for reasons that have nothing to do with the design, and the project would take days.
- **B: Gemini paid tier.** Would work, but needs a billing account on a card; not available.
- **C: DeepSeek, Flash to plan and build, V4 Pro to review (chosen).** Cheap enough for every run
  the assignment needs, and the reviewer runs on a different and stronger model than the
  builder, which is what ADR-008 wanted from the start.

## Decision

- A third backend, `workflow/autose/llm_openai.py`, runs the same agent loop on the OpenAI chat
  format with DeepSeek's base URL. `make_agent` picks it for `deepseek-*` model names, so the
  tools, gates and workflow are unchanged. The key is the `DEEPSEEK_API_KEY` secret.
- Models: planner, testability check and builder use `deepseek-flash`; the reviewer uses
  `deepseek-v4-pro`. Each role keeps a fallback list (from ADR-011's last update), and the
  reviewer still skips whichever model built the change.
- The budget caps of ADR-009 apply again in dollars, priced at DeepSeek's peak rates so the
  estimate errs high. The provider-side limit is the account balance: top up only what the
  assignment needs.
- No extra waiting between calls; temporary errors (429, 5xx, timeouts) are retried with short
  waits, and an account with no balance (HTTP 402) stops the stage at once with a clear message.
- The Gemini and Claude backends stay. Putting their model names back in `.autose.yml` switches
  provider again.
- Update after the first DeepSeek runs ([issue #2, run 45185188894](https://github.com/Anjaliy474/tinydb/actions/runs/45185188894)
  and [review of PR #16, run 45185349135](https://github.com/Anjaliy474/tinydb/actions/runs/45185349135)):
  both stopped on ADR-009's turn limits (builder 20, reviewer 12), which were set for Claude.
  DeepSeek tends to make one small tool call per turn. The limits are now planner 12, builder
  40 and reviewer 25, with token caps raised to match (600K, 3M and 1.5M per round); the
  dollar caps are unchanged and still bound the cost. The prompts now ask for several tool calls
  per turn, and every stage saves its agents' tool logs (`*_agent_log.json`) as an artifact, so
  a person can see how the turns were spent. These logs are never given to another agent.

- Update (same day): I chose to run every role, the reviewer included, on `deepseek-flash`
  (DeepSeek V4.1 Flash-1017), to keep one model and the lowest cost. That gives up the stronger,
  different reviewer model described above; reviewer independence now rests on the separate job,
  the missing upstream artifacts, the skeptical prompt and the evidence-gated rubric (ADR-008).
  Experiment A in `experiment/variants.md` checks what the bigger reviewer model would add: on the
  seeded PRs it caught the same bugs, but it was the only setup to route the design problem in S1
  to the design stage.

## Consequences

### Positive

- Runs no longer depend on a free quota that resets once a day.
- Builder and reviewer are different models of different size (Flash and V4 Pro), which
  strengthens reviewer independence compared with ADR-011.
- The five Gemini runs stay in the record as evidence for the harness changes they caused
  (ADR-011's updates and ADR-012).

### Negative

- It costs money, a small amount per run. Token use and estimated cost are recorded in each
  run's `run_state.json`.
- Builder and reviewer now come from the same company, so they may share some blind spots even
  though they are different models.
- DeepSeek's pricing page doesn't name the currency; I assume US dollars.
- Prompts and code are sent to DeepSeek's servers. That's fine for this public repo, but would
  need thought for private code.
