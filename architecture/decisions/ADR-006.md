# ADR-006: Role-Tiered Multi-Model Routing with Cross-Family Review

- **Decision ID:** D6 (Models)
- **Date:** 2026-11-23

## Status

Superseded by [ADR-011](ADR-011.md). There was no paid Anthropic or OpenAI API access for the first run, so the agents moved to the Gemini free tier.

## Context

Each role in our three-agent architecture has different reasoning, speed, and cost requirements:
- **Agent 1 (Planner)** and **Agent 2 (Builder)** require strong code comprehension, accurate multi-file editing, and reliable tool use without burning frontier-tier pricing on every turn.
- **Stage 1 Testability Check** needs only a fast, binary rubric check over short acceptance criteria.
- **Stage 5 (Release)** uses **no LLM at all** (ADR-001), saving tokens completely.
- **Agent 3 (Independent Reviewer)** benefits from a **different model family** than the Builder to avoid correlated blind spots and self-preference bias when evaluating generated patches.

The workflow must also stay within a hard provider spending cap and log total token usage for every run.

### Options Considered

- **Option A — Single Frontier Model for All Roles (e.g., Claude Opus 5.5 everywhere):** High capability, but expensive ($4/$20 per 1M input/output tokens per [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing)) and loses cross-family diversity between Builder and Reviewer.
- **Option B — Single Budget Model for All Roles (e.g., Claude Haiku 5.5 or GPT-5 mini):** Lowest per-token price ($0.10/$0.50 for Haiku 5.5 per [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing); GPT-5 mini per [OpenAI pricing](https://openai.com/api/pricing/)), but lower coding accuracy triggers extra Stage 3↔4 retry loops, increasing total token spend.
- **Option C — Role-Tiered Routing with Cross-Family Reviewer and Env-Var Configuration (Chosen):** Match model tier to role complexity, eliminate LLM calls in Stage 5, and separate Reviewer and Builder model families.

## Decision

Model assignments are parameterized via workflow environment variables (`PLANNER_MODEL`, `BUILDER_MODEL`, `JUDGE_MODEL`, `REVIEWER_MODEL`) with the following defaults:

| Component | Default Model | Base Pricing (per 1M in / out) | Rationale |
| :--- | :--- | :--- | :--- |
| **Agent 1 (Planner: Stages 1–2)** | **Claude Sonnet 5.5** ([Anthropic](https://www.anthropic.com/claude/sonnet)) | $2.00 / $10.00 ([pricing](https://platform.claude.com/docs/en/about-claude/pricing)) | Strong specification and architecture planning at half the cost of Opus 5.5, with 0.05x prompt-cache reads. |
| **Agent 2 (Builder: Stages 3–4)** | **Claude Sonnet 5.5** | $2.00 / $10.00 | High coding and debugging accuracy; prompt caching amortizes repeated file reads during bounded Stage 3↔4 retries. |
| **Stage 1 Testability Judge** | **Claude Haiku 5.5** | $0.10 / $0.50 for prompts up to 100K tokens ([pricing](https://platform.claude.com/docs/en/about-claude/pricing)) | Fast, ultra-low-cost binary rubric check over `spec.md` acceptance criteria. |
| **Stage 5 (Release)** | **None (Deterministic)** | $0.00 | Pure Git/`gh` CLI script + template rendering; zero LLM tokens. |
| **Agent 3 (Reviewer: Stage 6)** | **OpenAI GPT-5** ([OpenAI API](https://developers.openai.com/api/docs/pricing)) | See [OpenAI pricing](https://openai.com/api/pricing/) | Distinct model family from the Claude Builder, reducing correlated errors and self-preference bias. *(Fallback: if `OPENAI_API_KEY` is not set, the harness uses Claude Opus 5.5 with the same adversarial prompt. It is a different model from the Builder but the same family, and the reviewer model actually used is recorded in `run_state.json` and `review.md`.)* |

Every LLM wrapper logs `input_tokens`, `output_tokens`, `cached_tokens`, and estimated USD cost per stage into `run_state.json`.

## Consequences

### Positive

- **Token & Cost Efficiency:** Eliminating LLM calls in Stage 5, using Haiku 5.5 for the Stage 1 rubric check, and enabling prompt caching on Sonnet 5.5 keeps per-run cost strictly bounded.
- **Cross-Family Review Independence:** Reviewing Claude-written diffs with GPT-5 catches blind spots that a same-family reviewer tends to overlook.
- **Easy A/B Experimentation:** Swapping `REVIEWER_MODEL` via environment variable enables direct comparison of cross-family vs. same-family review without code changes.

### Negative

- **Two API Keys Required (for Default Cross-Family Mode):** Requires storing both `ANTHROPIC_API_KEY` and `OPENAI_API_KEY` as repository secrets and setting hard spending caps on both providers.
- **Thin Multi-Provider Client Needed:** Requires a small adapter supporting both Anthropic and OpenAI APIs (roughly ~60 lines of Python).
