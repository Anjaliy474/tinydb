# ADR-007: Deterministic-First Stage Gates with Narrow Stage 1 Rubric Check

- **Decision ID:** D7 (Checks)
- **Date:** 2026-11-23

## Status

Accepted, except that its "halt on the first failed check" rule for Stages 1 and 2 is superseded by [ADR-012](ADR-012.md): the planner now gets one revision with the checker's reasons.

## Context

Each of the six SDLC stages must pass an explicit check before handing over to the next stage; if a check fails, the stage must explain why in its artifact and halt (or trigger a bounded retry where permitted).

Relying on agents to self-certify their own outputs is unreliable—LLMs frequently declare incomplete specs "testable" or broken patches "passing." Conversely, using an LLM judge for stages that already have objective program oracles (file existence, compilation/build, test suite exit codes, CI status) wastes tokens and introduces flakiness.

### Options Considered

- **Option A — Agent Self-Certification:** Let each agent declare pass/fail at the end of its turn. Rejected due to high hallucination and optimism bias.
- **Option B — LLM-as-a-Judge at All Six Stages:** Run a separate LLM evaluator after every stage. Rejected because Stages 2–5 have deterministic ground-truth checks; LLM judges add unnecessary tokens and nondeterminism.
- **Option C — Deterministic-First Gate Runner (`workflow/gates.py`) + Narrow Haiku Rubric for Stage 1 Only (Chosen):** Use deterministic programmatic checks wherever an objective oracle exists, and reserve a lightweight LLM rubric solely for Stage 1 semantic testability.

## Decision

A standalone deterministic module (`workflow/gates.py`), executed outside the agent's control, holds **final pass/fail authority** for all six stages. On failure, `workflow/gates.py` appends a `## Gate Failure Diagnostics` section to the stage artifact and exits non-zero.

### Stage Gate Matrix

| Stage | Artifact | Deterministic Check | LLM Judge | Pass/Fail Authority |
| :--- | :--- | :--- | :--- | :--- |
| **1. Requirements** | `spec.md` | Valid YAML frontmatter; `>= 2` numbered criteria (`AC-1..N`) with concrete preconditions & expected outcomes; rejects vague unbounded words ("fast", "clean", "better"). | **Haiku 5.5** binary testability rubric per `AC-i` (observable & falsifiable by automated test). | `workflow/gates.py` (requires BOTH schema AND all `AC-i` to pass). |
| **2. Design** | `design.md` | Extracts planned file paths & symbol names: every existing file must exist in repo (new files tagged `[NEW]`); named existing functions/classes must exist in those files (via static AST/symbol grep); all paths must fall inside `.autose.yml` `allowed_edit_paths`. | None | `workflow/gates.py` |
| **3. Implementation** | `diff.patch` | Non-empty diff; all modified paths within `allowed_edit_paths` (never `.github/` or `workflow/`); `git apply --check` succeeds; configured `build_cmd` from `.autose.yml` exits `0`. | None | `workflow/gates.py` |
| **4. Testing** | `test_report.md` | Runs configured `test_cmd` (full existing suite + new tests) with exit code `0`; verifies every `AC-i` from `spec.md` maps to at least one executed, passing test identifier; zero newly skipped tests. | None | `workflow/gates.py` (triggers Stage 3 retry on failure, max 3 attempts per cycle, then at most one Stage 2 escalation; ADR-002). |
| **5. Release** | `pr.md` + PR link | `gh pr view` confirms PR is `OPEN` in the fork repository (never upstream); `pr.md` contains PR URL; the in-run `ci-r1` job (ADR-002) succeeded on the PR head SHA and its `autose/ci` commit status is `success`. | None | `workflow/gates.py` |
| **6. Review** | `review.md` | Validates structured verdict JSON (`verdict` in `{APPROVE, REQUEST_CHANGES}`, `routing_target` in `{implementation, design, none}`, non-empty executed verification evidence, file/line citations for defects); verifies `round <= 2`; checks that the verdict line of the posted `COMMENT` review matches `review.md`. | None | `workflow/gates.py` |

## Consequences

### Positive

- **Objective, Reproducible Gates:** Five of six stages are gated with zero LLM judgment, eliminating hallucinated passes and saving tokens.
- **Repository-Agnostic Verification:** Reading `build_cmd`, `test_cmd`, and `allowed_edit_paths` from `.autose.yml` lets the exact same gate runner verify Python, TypeScript, Go, or any other repo.
- **Clear Failure Diagnostics:** Every failed gate writes exact missing symbols, build errors, or failing test tracebacks directly into the stage artifact.

### Negative

- **Strict Artifact Schema Required:** Agents must follow exact Markdown/YAML formatting (`AC-1`, file/symbol blocks, verdict JSON). A single lightweight format-repair pass is permitted only if parsing fails on syntax rather than substance.
- **Static Symbol Check Does Not Judge Design Quality:** Stage 2's gate verifies that named files and functions are real; qualitative design flaws are caught downstream by Stage 4 tests and Stage 6 Independent Review.
