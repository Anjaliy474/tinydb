# ADR-008: Four-Pillar Reviewer Independence and Anti-Sycophancy Enforcement

- **Decision ID:** D8 (Reviewer Independence)
- **Date:** 2026-11-23

## Status

Accepted

## Context

Stage 6 requires an independent reviewer agent that sees **only** the issue, the PR diff, and the repository at the PR head commit, can run code/tests itself, has **no push permission**, and never sees the implementer's conversation or reasoning.

Even when isolated, LLM reviewers tend toward **sycophantic approval** ("looks good to me") when shown a clean-looking diff—a failure mode highlighted in [Anthropic's harness design research](https://www.anthropic.com/research/harness-design-long-running-apps). Preventing rubber-stamping requires combining structural isolation with mandatory execution-backed verification and empirical calibration.

### Options Considered

- **Option A — Same-Session Self-Review:** Ask Agent 2 to review its own diff. Rejected because it violates independence and suffers severe confirmation bias.
- **Option B — Isolated Static Diff-Only Review:** Run a separate job that reads `git diff` without executing tests. Rejected because subtle behavioral regressions and missing edge-case coverage often require running the test suite or targeted probes to detect.
- **Option C — Four-Pillar Isolation + Execution-Backed Adversarial Rubric (Chosen):** Enforce independence at the Actions job, artifact, model-family, and prompt/gate layers simultaneously.

## Decision

We enforce reviewer independence and prevent rubber-stamping through **four concrete controls**:

1. **Isolated GitHub Actions Job & Read-Only Repo Token:**
   - Stage 6 runs in its own job (`review-r1` / `review-r2`) on a fresh runner with `permissions: { contents: read, issues: read, pull-requests: write }`. `issues: read` lets it fetch the original issue; it has no `issues: write`, so it cannot touch the run checkpoint (ADR-004).
   - It checks out the PR head commit directly and has zero push or merge permissions at the GitHub API level.
   - It posts its review as a `COMMENT` review (`gh pr review --comment`), never `--approve`. GitHub does not let the bot that opened the PR approve it, and approval and merge must come from a person anyway (ADR-005).

2. **Strict Artifact Isolation (ADR-003):**
   - The review job does **not** download `spec.md`, `design.md`, `test_report.md`, `pr.md`, or any Stage 1–5 logs. It receives only the original issue (`gh issue view`), `git diff <base>...HEAD`, and the repository checkout at PR HEAD.

3. **Cross-Family Model Separation (ADR-006):**
   - Agent 3 runs on a different model family (**OpenAI GPT-5**) than Agents 1–2 (**Claude Sonnet 5.5**), breaking shared-weight blind spots.

4. **Anti-Sycophancy Adversarial Protocol & Evidence Gate:**
   - **Skeptical System Prompt:** Instructs Agent 3 to treat the diff as untrusted external code and systematically audit four mandatory dimensions:
     1. *Issue Fidelity:* Does the diff satisfy every requirement in the original issue without unintended scope creep?
     2. *API & Invariant Preservation:* Are public contracts, backwards compatibility, and repository architecture invariants preserved?
     3. *Edge Cases & Error Handling:* Are boundary conditions, invalid inputs, and failure paths handled safely?
     4. *Test Adequacy:* Do the new tests genuinely exercise the changed behavior rather than tautologically mirroring the implementation?
   - **Mandatory Test Execution:** Agent 3 must execute the repository's configured `test_cmd` (and may run targeted edge-case probes in its ephemeral worktree) and record the command and exit code.
   - **Evidence-Gated Approval (ADR-007):** `workflow/gates.py` rejects any `APPROVE` verdict that omits recorded test execution output or skips any of the four audit dimensions.
   - **Blocking vs. Non-Blocking Distinction:** Only concrete, file-and-line-cited defects trigger `REQUEST_CHANGES` (with `routing_target: "implementation"` for code/test bugs or `"design"` for flawed approaches); stylistic suggestions stay non-blocking.
   - **Seeded-PR Calibration:** Before live evaluation, Agent 3 is benchmarked on `experiment/seeded_prs/` (diffs containing known planted defects vs. clean patches) to verify it rejects buggy PRs and approves clean ones.

## Consequences

### Positive

- **Auditable Structural Independence:** Anyone inspecting `.github/workflows/autose.yml` can verify `contents: read`, zero upstream `download-artifact` calls, and distinct `REVIEWER_MODEL`.
- **Catches Spec Misinterpretations:** Reading the original issue instead of `spec.md` allows Agent 3 to detect when Agent 1 misread the user's request and route `design` rework back to Stage 2.
- **Empirical Anti-Sycophancy Validation:** Testing against `seeded_prs/` measures true-positive defect detection and false-positive rejection rates objectively.

### Negative

- **Potential Nitpick Rejections:** A skeptical prompt can occasionally trigger an unnecessary Round 2 rework on borderline issues, mitigated by the explicit blocking vs. non-blocking rule.
- **Bounded to Two Rounds:** Any defect still unresolved after Round 2 is escalated cleanly to the human maintainer via `review.md` rather than looping further.
