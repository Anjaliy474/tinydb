# ADR-011: Run the agents on the Gemini free tier

- **Decision ID:** D6 (Models), revisited
- **Date:** 2026-11-23
- **Supersedes:** ADR-006

## Status

Accepted

## Context

ADR-006 put the planner and builder on Claude Sonnet 5.5 and the reviewer on GPT-5 (or Claude
Opus 5.5). When it was time for the first run, it turned out I can't use the Anthropic API for
this project: the API is billed separately from a Claude subscription, and I don't have an
OpenAI key either. The workflow had not run yet, so no result depended on ADR-006.

What I do have is a Google account. The Gemini API has a free tier (an API key from Google AI
Studio, no card needed). Two things about that free tier shape the design:

- Limits are small and set per model: a few requests per minute and a daily cap per model.
  Google describes the free tier as best effort, and the daily caps have been cut before.
  One full run needs roughly 50 to 80 model calls.
- It's free, so a dollar cap can't stop a runaway stage any more.

ADR-008 also wants the reviewer to be a different model from the builder, so it doesn't share
the builder's blind spots.

### Options considered

- **A: pay for the Anthropic API anyway.** Matches ADR-006 exactly, but I can't use it.
- **B: one Gemini model for every role.** Simplest, but all calls hit one model's daily cap, and
  the reviewer would be the same model as the builder.
- **C: Gemini free tier, a different model per role (chosen).** Spreads the calls over several
  per-model limits and keeps the reviewer on a different model from the builder.
- **D: GitHub Models for the reviewer (an OpenAI model, free with the workflow's token).** Would
  give a truly different model family, but its free request size is small for a diff plus
  context. Kept as a possible experiment, not the default.

## Decision

- The agent loop gets a second backend (`workflow/autose/llm_gemini.py`) next to the Claude one.
  `make_agent` picks it from the model name, so tools, gates and the workflow don't change.
- Models in `.autose.yml`, picked from what the "AutoSE check models" workflow showed actually
  answers on this key's free tier (run 45168092585): planner `gemini-3.5-flash`, testability
  check `gemini-3.5-flash-lite`, builder `gemini-3.6-flash`, reviewer `gemini-3.5-flash`.
  My first choice was the 2.5 models, but they are closed to new users. A Pro model as
  reviewer wasn't possible either: `gemini-3.1-pro-preview` doesn't exist for this key and the
  `gemini-4-*` models have no free quota. `gemini-3.7-flash` and `gemini-3.8-flash` were
  overloaded (HTTP 503) when I checked, so they aren't used yet.
- So the reviewer is a different model from the builder, but not a stronger one. Planner and
  reviewer share a model; they never run at the same time, and the reviewer still starts with
  no context from the planner.
- Every Gemini call waits and retries on a per-minute 429 (using the delay the API suggests), up
  to 10 minutes per call. The agent job timeouts go up to match (planner 20, builder 45,
  reviewer 30 minutes).
- Update after the first run on issue #3: the planner spent its whole 20 minutes in the planning
  stage, mostly waiting on rate limits while it read files one call at a time. Three changes
  followed: (1) a 429 that names the *daily* quota now stops the stage at once with a clear
  message instead of retrying until the job times out; (2) calls to the same model are spaced
  at least 4 seconds apart; (3) the planner gets the file list and ARCHITECTURE.md in its first
  message, so it doesn't spend calls on listing directories, and it moved to
  `gemini-3.5-flash-lite`, which has more free requests, with 8 turns instead of 10.
- Update after the third run on issue #3 ([run 45173736214](https://github.com/Anjaliy474/tinydb/actions/runs/45173736214)):
  planning passed, but `gemini-3.6-flash` answered the builder's first call with 503 and then
  504, and the job crashed because 504 wasn't treated as temporary. Now 502/504 are retried too,
  and an API error that won't go away ends the attempt cleanly with a report. The builder moved
  to the steadier `gemini-3.5-flash` (it makes the most calls) and the reviewer to
  `gemini-3.6-flash`. That also puts the reviewer back on the newer model, closer to what
  ADR-008 wanted.
- Free-tier calls count as $0, so ADR-009's dollar caps are backed by per-stage token caps:
  planner 300K, builder 1.2M per round, reviewer 500K per round.
- The Claude code path stays. Putting `claude-*` names back in `.autose.yml` and adding
  `ANTHROPIC_API_KEY` returns to ADR-006.

## Consequences

### Positive

- The workflow can run at no cost, which is the only way it can run for this project.
- The reviewer is still a different model from the builder (3.6 Flash reviews what 3.5 Flash
  built), and it still never sees the builder's work beyond the diff (ADR-008 is otherwise
  unchanged).
- Switching provider is a config change, which also makes a model experiment easy.

### Negative

- The reviewer is the same model family as the builder, so some blind spots may be shared. This
  weakens one of ADR-008's four controls; the other three (separate job, no upstream artifacts,
  evidence-gated rubric) remain. I'll check how much this matters on the seeded PRs.
- Runs are slower and can fail on a bad day if the free daily quota runs out. A failed run says
  so in its artifact and can be restarted with `/autose`.
- Free-tier prompts may be used by Google to improve its models. The repo and issues are public,
  so nothing private is sent, but it rules out using this setup on a private repo.
- Cost in the report is reported as tokens only; the dollar figure is $0.
