# ADR-003: Minimal Artifact-Only Hand-offs with Strict Information Hiding

- **Decision ID:** D3 (Hand-offs)
- **Date:** 2026-11-23

## Status

Accepted

## Context

Passing full conversation histories between agents wastes tokens, propagates untrusted issue text into code-execution stages, and destroys reviewer independence by exposing upstream rationalizations. Conversely, passing vague one-sentence summaries loses exact acceptance criteria, file paths, and test failure traces.

The hand-off contract must be **repository-agnostic**, **token-minimal**, and enforce strict information barriers—especially for Stage 6 (Independent Review), which may only see the issue, the PR diff, and the repository at the PR head commit.

### Options Considered

- **Option A — Forward Full Agent Transcripts:** Pass complete message logs from stage to stage. Rejected because it inflates input tokens quadratically, introduces anchor bias, and violates Stage 6 independence.
- **Option B — Free-Form Prose Summaries:** Ask each agent to summarize its work in prose. Rejected because prose omits exact function signatures, structured acceptance criterion IDs, and deterministic routing metadata.
- **Option C — Minimal Schema-Validated Markdown Artifacts + Explicit Omissions (Chosen):** Every stage reads only its declared input artifacts and scoped repository files; raw reasoning traces are never passed across stage boundaries.

## Decision

Agents communicate exclusively through **six fixed Markdown artifacts** (`spec.md`, `design.md`, `diff.patch`, `test_report.md`, `pr.md`, `review.md`), each prefixed with a compact YAML frontmatter block (`stage`, `round`, `status`, `gate_passed`). Raw LLM transcripts and chain-of-thought logs are **never** forwarded to downstream stages.

### Stage Hand-off Contract

| Stage | Inputs Provided | Deliberately Omitted | Why Omitted |
| :--- | :--- | :--- | :--- |
| **1. Requirements** (Agent 1) | Sanitized issue title/body (`<untrusted_issue_data>`), A1 spec skill, repo `README.md` | Full source code, git history, unrelated issues | Keeps requirements focused on observable behavior rather than premature code details; minimizes input tokens. |
| **2. Design** (Agent 1) | `spec.md`, `ARCHITECTURE.md`, read-only repo tree (plus `review.md` on Round 2 `design` rework) | Raw issue comments, Stage 1 tool traces | Grounds the plan in verified acceptance criteria and documented architecture. |
| **3. Implementation** (Agent 2) | `spec.md`, `design.md`, repo checkout on `autose/issue-<N>` (plus failing test trace on Stage 4 retry, or `review.md` on Round 2 `implementation` rework) | Raw issue body/comments, Agent 1 transcripts | Isolates code-editing from untrusted issue text; keeps edits scoped to `design.md`. |
| **4. Testing** (Agent 2) | `spec.md`, `diff.patch`, repo checkout with Stage 3 edits, configured test command | Agent 1 transcripts, raw issue comments | Ensures tests directly validate every `AC-i` in `spec.md` against the actual diff. |
| **5. Release** (Deterministic) | `spec.md`, `design.md`, `test_report.md`, `git diff --stat`, CI check status | Agent transcripts, secrets | Deterministic template renders `pr.md` with zero LLM tokens. |
| **6. Independent Review** (Agent 3) | Original issue title/body, `git diff <base>...HEAD`, read-only repo checkout at PR HEAD, ability to run configured test command | `spec.md`, `design.md`, `test_report.md`, `pr.md`, and ALL Stage 1–5 logs/transcripts | Enforces genuine independence: Agent 3 evaluates the actual diff against the original issue and codebase without seeing upstream justifications. |

## Consequences

### Positive

- **Lower Token Footprint:** Every agent starts with a clean, bounded context containing only the exact structured artifacts it needs.
- **Guaranteed Reviewer Independence:** Because `review-r1` and `review-r2` never download `spec.md`, `design.md`, or `test_report.md`, the reviewer can catch cases where Agent 1 misinterpreted the original issue.
- **Prompt Injection Containment:** Untrusted issue text is isolated to read-only Stage 1 and read-only Stage 6, never directly injected into Stage 3 code-editing prompts.

### Negative

- **Design Rationale Not Visible to Reviewer:** Because Agent 3 does not read `design.md`, non-obvious implementation trade-offs must be clear from the code/comments in the diff itself—matching standard human code review practice.
- **Schema Discipline Required:** Agents must follow exact Markdown/YAML artifact templates, enforced by deterministic schema checks (ADR-007).
